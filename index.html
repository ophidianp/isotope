Why the name

Same element. Different mass number.

An isotope is the same element with a different number. Isotope gives you the same mod with a different version number: it rewrites a mod made for one 26.x release so it links against the Minecraft you are actually running.

01 / Rewrite

Rewrites the mod

Moved classes, renamed methods and fields, mixin targets and access wideners are pointed at their new names, one release at a time.

What happens at launch

A few seconds of work. Cached after that.

Isotope runs before Fabric finishes setting up mods. The first launch rewrites and checks; later launches reuse the result unless something changed.

  1. Find out where the mod is from A · Detect

    It checks which game version actually contains the classes the mod uses. Mod metadata only narrows the guess, since "26.1 or newer" says little.

  2. Step through each release B · Rewrite

    A 26.1.2 mod on 26.3 goes through 26.2 first. Each step has its own table of moves and renames, worked out from Mojang's jars.

  3. Check it against your game C · Check

    Every reference is resolved the way Java would resolve it. Anything missing is listed with the classes that use it.

  4. Hold back certain crashes D · Protect

    If a class can no longer load, or the mod's initializer needs something that is gone, the mod stays out and the report says why.

  5. Load it like any other mod E · Load

    The rewritten copy is registered with Fabric as a normal mod. Your original jar is never touched.

Getting started

Two folders. That's the whole setup.

  1. Install Isotope

    Put the Isotope jar in your normal mods folder and start the game once.

  2. Add the other-version mods

    Put mods for other 26.x versions in isotope/mods, not in mods. Fabric would reject them there before Isotope runs.

  3. Read the report

    Start the game, then open isotope/report.txt to see what was redirected and what was left over.

Good to know

A few quick answers.

Will every mod work?

No. Many changes between releases are redesigns, not renames. 26.3 rewrote world generation and loot, for example, and no rename can bridge that. Isotope reports those and holds back mods that are certain to crash. In our test of real 26.1.x mods, 7 now load (counting the owo-lib library), 3 are being fixed, and 3 are held back.

Does it work on 1.21 or older?

No. Before 26.1, Minecraft was obfuscated and mods used a different toolchain, so it is out of scope. For older versions, look at Retromod.

Is it safe for my world?

Isotope never edits your original jars, and it keeps out mods it knows will crash. A loaded mod can still misbehave where the game changed underneath it, so back up worlds you care about before trying a rewritten mod.

Has it been tested on a client?

Not yet. It has been tested on a 26.3 dedicated server. Client-only parts of rewritten mods (rendering, screens) are rewritten and checked the same way, but have not been run in a real client.
